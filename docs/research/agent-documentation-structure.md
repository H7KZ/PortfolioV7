# Agent documentation structure for PortfolioV7

Verified against first-party documentation on 2026-09-24. The supplied handoff describes a different repository; its `apps/api`, `modules`, ADR collision, and Stripe/Gmail setup references do not apply here.

## Findings

- **Keep one source of agent rules.** Codex discovers `AGENTS.md` from the Git root down to its working directory, with closer files taking precedence. Claude Code now supports `AGENTS.md` directly in recent versions, but its default uses `CLAUDE.md` when both exist. Claude explicitly supports a `CLAUDE.md` containing `@AGENTS.md` and does not load the imported file twice. This repo already uses that arrangement: root `AGENTS.md` holds the rules and root `CLAUDE.md` contains only the import. Keep it instead of copying the rules. [Codex AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md) | [Claude Code project instructions](https://code.claude.com/docs/en/memory#agentsmd)
- **Keep always-loaded instructions short and concrete.** Anthropic says to include broadly applicable commands, conventions, and non-obvious architecture, and to move occasional workflows or long procedures elsewhere. Its guidance targets under 200 lines per `CLAUDE.md`; that is guidance, not a parser limit. OpenAI likewise advises against mandatory reading of a document stack before every edit. The root `AGENTS.md` can point to `README.md` for setup and `docs/PLAN.md` for design decisions without requiring both on every task. [Claude Code best practices](https://code.claude.com/docs/en/best-practices#write-an-effective-claudemd) | [Claude Code memory](https://code.claude.com/docs/en/memory#write-effective-instructions) | [OpenAI guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
- **Add nested agent files only for distinct, recurring local rules.** Claude Code loads root rules and the relevant subdirectory `CLAUDE.md` on demand when it reads there. Its monorepo guide uses one package file for package-specific conventions. Codex supports nested `AGENTS.md` from the project root to the working directory. PortfolioV7 currently has only the root pair, so there is no package-file shape to harmonize. If `apps/web`, `apps/cms`, or `packages/content` later needs persistent local rules, add a local `AGENTS.md` and verify Claude's loading behavior in the actual Claude Code version before adding an import shim. [Claude Code monorepo guide](https://code.claude.com/docs/en/large-codebases#layer-claudemd-files-by-directory) | [Codex AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **Use links for reference material, imports for instructions needed every session.** Claude Code expands `@path` imports immediately into context, including recursive imports up to four hops. The current `@AGENTS.md` is appropriate because those rules must load. Importing the long `README.md` or `docs/PLAN.md` would load both for every Claude session. [Claude Code imports](https://code.claude.com/docs/en/memory#import-additional-files) | [Claude Code best practices](https://code.claude.com/docs/en/best-practices#write-an-effective-claudemd)
- **Put manual setup in task-specific human docs.** This is a repo recommendation inferred from the sources above, not a vendor requirement. At audit time `README.md` included local development, deploy details, and a long one-time setup list. Move durable procedures into focused `docs/setup/` pages, keep prerequisites and outcomes rather than vendor button paths, and link them from a short README section. [Claude Code best practices](https://code.claude.com/docs/en/best-practices#write-an-effective-claudemd) | [OpenAI guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
